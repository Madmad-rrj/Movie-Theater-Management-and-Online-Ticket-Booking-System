# BE1 Handoff — Public Read API (đã kiểm chứng)

**Phạm vi:** 7 endpoint đọc công khai BE1 được kiểm chứng bằng integration test trên PostgreSQL Docker riêng (Testcontainers `postgres:16.4`, 65 test, chạy 2026-11-11). `GET /api/movies` (browse) cũng nằm trong bộ test và đã có kiểm chứng local trước đó. Không gồm booking/giữ ghế/Guest context/selection/payment (thuộc BE2).

**Trạng thái & giới hạn (tóm tắt):** endpoint trong bảng đã triển khai và đã kiểm chứng (xem [api-endpoints.md](api-endpoints.md)). Giới hạn đã ghi nhận: hành vi khi `date` có khoảng trắng đầu/cuối (browse showtimes) **chưa được contract quy định và chưa có test**; case hai allocation active “sold + held” cùng ghế/suất **không có test** vì ràng buộc DB `ux_active_seat` chặn insert (`released + held` cùng ghế đã kiểm chứng → `held`). Error envelope: `{ "error": { "code", "message", "details", "traceId" } }` (`details` là object, `{}` nếu trống; validation có `details.violations`).

## 2. ID mẫu để FE thử

- ID path/query (`movieId`, `cinemaId`, `showtimeId`, `seatId`, `seatTypeId`, `roomId`) và `version` là **chuỗi số thập phân** (bigint). Giá trị cụ thể **phụ thuộc DB/môi trường** (không cố định).
- **Cách lấy ID thực tế:** `GET /api/movies` → `data[].movieId`; `GET /api/cinemas` → `data[].cinemaId`; `GET /api/movies/{movieId}/showtimes?date=YYYY-MM-DD[&cinemaId=...]` → `data[].showtimeId`/`roomId`/`cinemaId`; `GET /api/showtimes/{showtimeId}/seats` → `data.seats[].seat.seatId`/`seatType.seatTypeId`.
- **Mẫu định dạng (ví dụ từ lượt chạy thật cô lập):** `movieId="1"`, `cinemaId="1"`, `showtimeId="1"`, `roomId="1"`, `seatId="1"`, `seatTypeId="1"`, `date="2026-11-14"` (timezone rạp, ví dụ `Asia/Ho_Chi_Minh`). Trên môi trường đã seed/demo, ID sẽ khác — FE phải dùng ID trả về từ API, không hard-code.

## 3. Điểm phối hợp với BE2 (ràng buộc BE1)

- **Đọc giá (pricing):** BE2/luồng checkout cần dùng `GET /api/cinemas/{cinemaId}/ticket-pricing` và `GET /api/ticket-categories` như nguồn đọc public hiện có; `amount` có thể bằng `0` (hợp lệ). Thiếu cấu hình giá rạp → `409 STATE_CONFLICT` (theo contract/kiểm chứng). BE1 không triển khai logic tính/quote/giữ giá của booking.
- **`booking_seat` chỉ đọc (read-only) qua API BE1:** `GET /api/showtimes/{showtimeId}/seats` chỉ **đọc** allocation (`held`/`sold`/`released`) để tính availability; **không ghi DB**, không lộ thông tin booking/khách. Việc tạo/giữ/bán/giải phóng ghế, Guest/selection/payment thuộc BE2 — BE2 chịu trách nhiệm ghi và nhất quán trạng thái; BE1 không cung cấp endpoint ghi.
- **Public showtime:** chỉ `status = "scheduled"` (rạp active, phim public) được xem; `date` lọc theo ngày của timezone rạp (đã kiểm chứng ranh giới). Suất/ID ngoài tập public → `404`.
- **ID & version:** truyền/nhận dưới dạng chuỗi số thập phân (không ép kiểu số nguyên 53-bit ở client).
